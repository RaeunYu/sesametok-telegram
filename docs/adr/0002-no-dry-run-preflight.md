# 발신 전 `dry_run` 확인 단계를 두지 않는다

백엔드 인수인계 문서는 "dry_run → 사용자 확인 → send" 2단계를 권장하지만, `dry_run`은
**대상 해석만** 하고 대상 방의 창이 열려 있는지는 검사하지 않는다(AX 창 매칭은 실제 발신
시점에 일어난다). 즉 미리보기는 사용자가 진짜로 알고 싶은 것 — "지금 보내면 성공할까?" — 에
답하지 못하고 거짓 확신만 준다. 확인 단계는 왕복 지연만 늘리고 실패율은 그대로다.

대신 답장 없이 그룹에 쓴 텍스트를 **즉시 발신**하고, 결과를 같은 메시지의 상태로 보여준다
(`⏳ → ✅ / ⚠️ 미확인 / 🚪 창 닫힘`). 실패했을 때만 재시도 버튼을 제공하며, 재시도는 항상
**새 `client_request_id`** 로 나간다.
